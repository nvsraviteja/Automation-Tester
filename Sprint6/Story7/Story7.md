# SQL Cheat Sheet — Sprint 6, Story 7
### Topic: SQL Constraints

---

## 0. Overview

| Constraint | Purpose |
|---|---|
| `PRIMARY KEY` | Unique identity for every row |
| `FOREIGN KEY` | Links two tables |
| `UNIQUE` | Prevents duplicate values |
| `NOT NULL` | Prevents NULL values |
| `CHECK` | Restricts valid values |
| `DEFAULT` | Provides a default value |
| `AUTO_INCREMENT` | Automatically generates IDs |

Constraints are rules applied to table columns to enforce **data accuracy and integrity** — they prevent invalid data from ever being inserted or updated.

---

## 1. PRIMARY KEY

Uniquely identifies each row in a table. Combines `UNIQUE` + `NOT NULL` behavior.

```sql
CREATE TABLE Employee (
    EmpID INT PRIMARY KEY,
    EmpName VARCHAR(50)
);

-- Add to an existing table
ALTER TABLE Employee ADD PRIMARY KEY (EmpID);
```

**Key points**
- Cannot contain duplicate or `NULL` values.
- Only **one** primary key allowed per table (though it can span multiple columns — composite key).

---

## 2. FOREIGN KEY

Links a column in one table to the **primary key** of another table, enforcing referential integrity between them.

```sql
CREATE TABLE Department (
    DeptID INT PRIMARY KEY,
    DeptName VARCHAR(50)
);

CREATE TABLE Employee (
    EmpID INT PRIMARY KEY,
    EmpName VARCHAR(50),
    DeptID INT,
    FOREIGN KEY (DeptID) REFERENCES Department(DeptID)
);
```

**Key points**
- Prevents inserting an `Employee` row with a `DeptID` that doesn't exist in `Department`.
- Can contain duplicate values and `NULL`s (unlike primary key).
- Can define behavior on delete/update of the parent row:
```sql
FOREIGN KEY (DeptID) REFERENCES Department(DeptID)
ON DELETE CASCADE
ON UPDATE CASCADE;
```

---

## 3. UNIQUE

Ensures all values in a column are **distinct** — but unlike primary key, allows `NULL` (typically one `NULL`, depending on the RDBMS).

```sql
CREATE TABLE Employee (
    EmpID INT PRIMARY KEY,
    Email VARCHAR(100) UNIQUE
);

-- Add to an existing column
ALTER TABLE Employee ADD CONSTRAINT uq_email UNIQUE (Email);
```

**Key point:** A table can have **multiple** `UNIQUE` constraints, but only **one** `PRIMARY KEY`.

---

## 4. NOT NULL

Ensures a column **cannot** store a `NULL` (empty/missing) value.

```sql
CREATE TABLE Employee (
    EmpID INT PRIMARY KEY,
    EmpName VARCHAR(50) NOT NULL,
    Email VARCHAR(100) NOT NULL
);
```

**Key point:** Applied to columns where a value is **mandatory** for every row (e.g., a name field shouldn't ever be blank).

---

## 5. CHECK

Restricts the values allowed in a column based on a **condition** — the insert/update fails if the condition evaluates to false.

```sql
CREATE TABLE Employee (
    EmpID INT PRIMARY KEY,
    Age INT CHECK (Age >= 18),
    Salary DECIMAL(10,2) CHECK (Salary > 0)
);

-- Multiple conditions combined
CREATE TABLE Employee (
    EmpID INT PRIMARY KEY,
    Age INT,
    CHECK (Age >= 18 AND Age <= 65)
);

-- Add to an existing table
ALTER TABLE Employee ADD CONSTRAINT chk_age CHECK (Age >= 18);
```

**Key point:** Useful for enforcing business rules directly at the database level (e.g., age limits, positive salary, valid status values).

---

## 6. DEFAULT

Assigns an **automatic value** to a column when no value is explicitly provided during insert.

```sql
CREATE TABLE Employee (
    EmpID INT PRIMARY KEY,
    Status VARCHAR(20) DEFAULT 'Active',
    JoiningDate DATE DEFAULT (CURRENT_DATE)
);

-- Insert without specifying Status -> defaults to 'Active'
INSERT INTO Employee (EmpID) VALUES (101);
```

**Key point:** The default value is only used when the column is **omitted** from the `INSERT` statement — explicitly inserting `NULL` will still store `NULL` (unless combined with `NOT NULL`).

---

## 7. AUTO_INCREMENT

Automatically generates a **unique, incrementing number** for a column — typically used with `PRIMARY KEY` columns like ID fields, so you don't need to manually assign IDs.

```sql
-- MySQL syntax
CREATE TABLE Employee (
    EmpID INT AUTO_INCREMENT PRIMARY KEY,
    EmpName VARCHAR(50)
);

-- Insert without specifying EmpID -> auto-generated
INSERT INTO Employee (EmpName) VALUES ('John');
INSERT INTO Employee (EmpName) VALUES ('Priya');
-- EmpID will be 1, 2, ... automatically
```

**Key points**
- MySQL: `AUTO_INCREMENT`
- SQL Server: `IDENTITY(1,1)`
- PostgreSQL: `SERIAL` or `GENERATED ALWAYS AS IDENTITY`
- Oracle: `GENERATED BY DEFAULT AS IDENTITY` or sequences
- Syntax differs by RDBMS, but the concept (auto-generated unique sequential value) is the same.

---

## Full Example — All Constraints Together

```sql
CREATE TABLE Employee (
    EmpID INT AUTO_INCREMENT PRIMARY KEY,
    EmpName VARCHAR(50) NOT NULL,
    Email VARCHAR(100) UNIQUE,
    Age INT CHECK (Age >= 18),
    Status VARCHAR(20) DEFAULT 'Active',
    DeptID INT,
    FOREIGN KEY (DeptID) REFERENCES Department(DeptID)
);
```

## Quick Reference Table

| Constraint | Allows Duplicates? | Allows NULL? | Count per Table |
|---|---|---|---|
| `PRIMARY KEY` | No | No | 1 |
| `FOREIGN KEY` | Yes | Yes | Multiple |
| `UNIQUE` | No | Yes (usually 1 NULL) | Multiple |
| `NOT NULL` | N/A | No | Multiple (per column) |
| `CHECK` | N/A | N/A (depends on condition) | Multiple |
| `DEFAULT` | N/A | N/A | One per column |
| `AUTO_INCREMENT` | No (auto-unique) | No | Typically 1 (on the PK) |
